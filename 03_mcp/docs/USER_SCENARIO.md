# User Scenario — Stage 3. MCP

## 등장인물

| 역할 | 사용하는 웹 | 설명 |
| --- | --- | --- |
| 릴리즈 매니저 / AI 운영자 | Hub 웹 (8300) | 사이클 시작, 관제, Agent Trace·MCP Tools 점검 |
| 개발부서원 (최개발, 정개발) | Dev 웹 (8301) | Host의 발행 요청 처리: 티켓 수정, 버전 발행 |
| 검증부서원 (김검증, 이검증, 박검증) | QA 웹 (8302) | Host의 검증 요청 처리: 판정, 이슈 등록, 이관 또는 확정 결정 |
| Host AI (Claude) | - | 데모: 모든 업무를 도구로 직접 수행 / 실습: 부서 간 결과 전달 |

## 시나리오 1. 실습 — 사람이 일하고 AI가 잇는다

| 단계 | 담당 / 웹 | 사용자 행동 | 시스템 반응 |
| --- | --- | --- | --- |
| 1 | 매니저 / Hub | **실습 시작** | Claude가 `dev__request_release` 호출 → Dev 웹 "차례", 발행 요청 #N 카드 |
| 2 | 최개발 / Dev | **v1.0.0 발행** | Dev 시스템에 '완료 작업'. 2초 내 Hub가 폴링으로 발견 → Claude가 `qa__request_verification`, `dev__ack_work` |
| 3 | 검증부서원 / QA | 담당 항목 **실행** → PASS / FAIL(이슈 폼, AI 초안) | Hub 배너에 판정 진행 수, 타임라인에 부서원 작업이 실시간 표시 |
| 4 | 박검증 / QA | 모든 항목 판정 후 **Dev 이관** | QA 시스템에 이관 결정(완료 작업) → Claude가 `qa__transfer_issues` → `dev__register_tickets` → `dev__request_release` → `qa__ack_work` |
| 5 | 개발부서원 / Dev | 티켓 **착수 → 수정 완료** → 릴리즈 노트 → **v1.1.0 발행** | Claude가 검증 요청 전달, QA 웹 '수정 확인'에 ISSUE-1~3 |
| 6 | 검증부서원 / QA | 수정 확인, 회귀 TC-11 이슈 등록 → **Dev 이관** | 같은 방식으로 전달 |
| 7 | 반복 후 / QA | 전 항목 PASS → **버전 확정** | Claude가 `qa__approve_release` → 사이클 확정 |
| 8 | 매니저 / Hub | **Agent Trace** | 실행 열에 "사이클 시작", "Dev 발행 완료 전달 (v1.0.0)", "QA 이관 결정 전달 (v1.0.0)" … 전달마다 Claude의 도구 호출과 보고 |

관찰: Hub Overview 배너의 "폴링 n회, 전달 m회". 사람이 오래 일할수록 폴링 수만 늘어난다.

## 시나리오 2. 데모 — AI가 모든 일을 도구로

| 단계 | 사용자 행동 | 확인 내용 |
| --- | --- | --- |
| 1 | Hub **MCP Tools** | 두 서버에서 발견한 도구(데모용·조정용)와 스키마 |
| 2 | **데모 실행** | Claude가 발행 → 테스트 → 이슈 작성 → 이관 → 수정 → 재발행 → 승인 (도구 약 21회) |
| 3 | Dev 웹 / QA 웹 | "데모 사이클 — 관찰용", 작업자는 Host AI로 기록 |
| 4 | **Agent Trace** | 실행 "데모 사이클" 아래 모든 턴과 도구 호출 |

## 예외 상황

| 상황 | 시스템 반응 |
| --- | --- |
| Host 요청이 없는데 QA 웹에서 판정 | 409 "지금은 검증부서 차례가 아닙니다 (Host의 검증 요청이 없습니다)" |
| QA 웹에서 개발부서원으로 작업 | 403 (QA 시스템 명부에 없음) |
| 판정이 남았는데 이관/확정 | 버튼 비활성화, 사유 표시 |
| Host 재시작 | 진행 중이던 실습 사이클의 조정을 이어서 재개 (데모 사이클은 중단 처리). Host가 꺼져 있는 동안 끝낸 작업도 재기동 후 전달 |
| Hub에서 사이클 중단 | Host가 `cancel_work`로 Dev/QA의 진행 중 요청을 즉시 취소 → 두 작업대의 "차례"와 작업 버튼이 사라짐. QA 작업대에 "중단" 안내 |
| Dev가 일부 티켓만 수정하고 발행 | 미완료 티켓은 상태·담당자가 유지된다. QA는 다음 버전 검증 후 반영되지 않은 이슈를 다시 **Dev 이관**할 수 있다(액션바에 "이전 버전 미반영 n건 포함"). Host가 전달하면 Dev는 새 이슈만 접수하고 기존 티켓은 이어서 작업 |
| 전달 중 도구 오류 (실습) | 필수 도구가 모두 성공하지 않으면 완료 작업을 확인(ack)하지 않고 다음 폴링에서 다시 전달 (3회 실패 시 사이클 실패) |
| Dev MCP 중지 (데모) | Claude가 오류 결과를 보고 재시도·상황 분석 후 보고하고 종료 |

## 관찰 포인트 (학습)

- Dev와 QA는 서로를 모른다. 모든 연결이 Host의 MCP 도구 호출을 지난다(수직 구조).
- 사람의 장시간 작업은 MCP 도구 호출 하나로 표현할 수 없어, Host가 '완료 작업'을 폴링한다.
